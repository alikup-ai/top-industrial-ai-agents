# Top Industrial AI Agents

> Кураторский список LLM-агентных проектов, инструментов, бенчмарков и исследований, применимых в промышленных средах — SCADA, MES, историаны, промышленные протоколы, предиктивное обслуживание, computer vision на производстве, промышленные цифровые двойники.

## Зачем этот список

Общая экосистема агентного ИИ огромна и хорошо каталогизирована. Промышленные применения — нет. Большинство awesome-списков индексируют чат-ботов, кодинг-агентов и SaaS-продукты, но ни один не отвечает на вопрос, какие проекты реально работают, когда на другом конце — OPC UA-сервер, Modbus-контроллер или процессный историан, и когда неверное действие останавливает печь.

Этот список пытается ответить на более узкий вопрос: **какие агентные проекты переживают контакт с оперативной технологией (OT)?**

**В скоуп входят:** LLM-агенты для SCADA/DCS/MES/историана, коннекторы промышленных протоколов (OPC UA, Modbus, MQTT), OT-осознанные guardrails и слои допуска, бенчмарки и симуляторы для управления процессами, предиктивное обслуживание с LLM, промышленный computer vision, гибриды цифровых двойников с LLM.

**Вне скоупа:** универсальные агентные фреймворки (LangChain, AutoGen, CrewAI — см. [awesome-ai-agents][kurilyak]), кодинг-агенты, sales/CRM-агенты, непромышленный предиктив для чистого SaaS.

**Позиция куратора:** «Top» в названии означает пристрастность. Проекты должны (а) быть воспроизводимы или подтверждаемо развёрнуты, (б) явно решать промышленную задачу, (в) иметь публичную документацию. Маркетинговые лендинги без кода, демо или peer-review-статей отклоняются. Закрытый проект может попасть в список, если у него задокументированы промышленные внедрения — он помечается 🔒.

**Статус:** v0.2 — ранняя стадия, факт-чекнутый. Многие категории намеренно тонкие, потому что соответствующая ниша действительно пустая. Пустые категории помечены 🚧 и открыты для контрибуций.

[kurilyak]: https://github.com/slavakurilyak/awesome-ai-agents

## 🔌 Мосты к промышленным протоколам

### [winccoa/winccoa-ae-js-mcpserver](https://github.com/winccoa/winccoa-ae-js-mcpserver) — Официальный Siemens MCP для WinCC OA
Официальный MCP-сервер Siemens для WinCC Open Architecture. JavaScript, обширный функционал: датапоинты (чтение/запись/создание), OPC UA и MQTT, дашборды, алармы, архивы, управление процессами (Pmon), валидация PV-диапазонов, 1400+ встроенных иконок. **Включает встроенную модель ограничения записи**: администраторы могут отключать целые категории инструментов, чтобы блокировать запись в конфигурацию и runtime SCADA.
**Вердикт:** первый MCP от крупного вендора для промышленной SCADA и самый полнофункциональный промышленный MCP на сегодня. Сигнал принятия MCP в мейнстрим OT.

### [vogler75/winccua-mcp-server](https://github.com/vogler75/winccua-mcp-server) — Сторонний MCP для WinCC Unified
MCP-сервер для **WinCC Unified** (другой продукт Siemens, не путать с WinCC OA), через GraphQL API. Обзор объектов, чтение текущих и исторических значений тегов, активные и журналированные алармы, запись, сброс алармов.
**Вердикт:** полезное дополнение для площадок на WinCC Unified.

### [kukapay/opcua-mcp](https://github.com/kukapay/opcua-mcp) — Минимальный generic OPC UA MCP
Небольшой референсный MCP-сервер для OPC UA. Пять инструментов: чтение, запись, browse, множественное чтение/запись. Нет слоя политики, нет скоупинга, нет авторизационной модели — доступ на запись ничем не ограничен.
**Вердикт:** 6 звёзд, последняя активность май 2025 — это учебный пример, не production-инструмент. Включён как «наивный baseline», показывающий, почему OT-слой допуска необходим.

### 🚧 Modbus MCP-сервер — production-качества пока нет

### 🚧 MCP-сервер к историану — не найдено
Чтение исторических временных рядов через агента (PI, Alpha.Historian, Aveva Historian и т.п.) — распространённая потребность без публичной MCP-реализации. Большой пробел.

## 🛡️ OT-осознанные guardrails и слои допуска

### [meta-llama/PurpleLlama — LlamaFirewall](https://github.com/meta-llama/PurpleLlama/tree/main/LlamaFirewall)
Open-source guardrail-фреймворк Meta для LLM-агентов. Три основных сканера: **PromptGuard 2** (BERT-детектор jailbreak/injection), **AgentAlignmentCheck** (аудитор цепочки рассуждений), **CodeShield** (статический анализ кода), плюс кастомные regex-фильтры. Документирован статьёй (arXiv 2505.03574).
**Вердикт:** самый зрелый open-source guardrail на середину 2026. **Работает только на уровне текста — не понимает семантику процесса** (скорости изменения, блокировки, физические ограничения). Необходимый базовый слой для промышленного стека; недостаточный сам по себе.

### [NVIDIA-NeMo/Guardrails](https://github.com/NVIDIA-NeMo/Guardrails)
Программируемый guardrail-тулкит NVIDIA. Пять типов rails: input, dialog, retrieval, execution, output. Интегрируется с Nemotron Content Safety, Topic Control и Jailbreak Detect NIM. Недавно отвязан от LangChain (опционален). Активные релизы через 2026.
**Вердикт:** вторая крупная guardrail-платформа общего назначения. То же ограничение — нет OT-семантики — но богатый язык политик (Colang) делает потенциально расширяемым для промышленных правил.

### Исследовательский фронтир (2025–2026)

- **[AgentWall](https://arxiv.org/abs/2605.16265)** — перехват действий агента на уровне ОС: shell-команды, API-вызовы, файловые операции. Препринт (май 2026), публичного кода пока нет. По духу ближе всего к потребностям OT.
- **AgentGuardian** (arXiv 2601.10440) — обучаемые политики контроля доступа для LLM-агентов
- **ToolSafe** (arXiv 2601.10156) — pre-execution детекция безопасности на уровне шага
- **OneShield** (arXiv 2507.21170) — «следующее поколение guardrails» от IBM
- **[protectai/llm-guard](https://github.com/protectai/llm-guard)** — production-ориентированный security-тулкит для LLM

### 🚧 OT-осознанный слой допуска — в production не существует
Разрыв: guardrail, понимающий контекст процесса — что запись в `TIC-101`, формально допустимая (40°C в диапазоне), опасна, потому что текущее значение 22°C и скорость изменения нарушает safety-конверт. Siemens WinCC OA MCP имеет категорийные исключения; сообщество (`uebelmar-oa-mcp`) добавляет plant-specific rules (forbidden patterns `*_SAFETY_*`, `*_ESD_*`, operational limits). Но автономного, vendor-neutral, семантически-осознанного OT-guardrail **не существует**.

## 📊 Промышленные бенчмарки агентов

### [amazon-science/SOP-Bench](https://github.com/amazon-science/SOP-Bench)
2000+ задач в 12 доменах — тестирование агентов на стандартных операционных процедурах. Эксперт-написанные SOP, executable-интерфейсы с ground-truth, оценка по ECR, TSR, C-TSR. 11 frontier-моделей прогнаны; function-calling агенты ~64% TSR. Статья: arXiv 2506.08119 (v2, фев 2026, подана на KDD 2026).
**Вердикт:** самый авторитетный свежий бенчмарк для процедурных агентов. Домены индустриально-адъяцентные (Dangerous Goods, healthcare intake, логистика), но **не управление физическим процессом**.

### [IBM/AssetOpsBench](https://github.com/IBM/AssetOpsBench)
Флагманский Industry 4.0 бенчмарк IBM. **460+ сценариев**, 5 специализированных агентов (IoT, FMSR, TSFM, Work Order + оркестратор), мульти-агентные blueprint'ы (MetaAgent, AgentHive) — **всё поверх MCP**. Привязка к ISO-стандартам. HuggingFace Space Playground, challenge на IJCAI 2026. Университетские расширения (Columbia, Binghamton, Albany). Статья: arXiv 2506.03828.
**Вердикт:** самое активное сообщество вокруг промышленного бенчмарка в 2026. Фокус — жизненный цикл активов (мониторинг, планирование ТО, наряды), **не оперативный супервайзинг процесса в реальном времени**.

### [Leezekun/SOPBench](https://github.com/Leezekun/SOPBench)
Параллельный бенчмарк следования SOP (не путать с Amazon SOP-Bench). Семь customer-service доменов: банк, онлайн-маркет, DMV, healthcare, библиотека, отель, университет.
**Вердикт:** уже́ доменов, чем у Amazon, но методологически отличный — полезен для перекрёстной проверки.

### 🚧 Closed-loop бенчмарк оперативного управления — не существует
Ни один открытый бенчмарк не сажает агента супервайзером работающего динамического процесса с оценкой по нарушениям safety-конверта, числу вмешательств и качеству диагноза. **Крупная открытая ниша.**

## 🎛️ Симуляторы процессов для оценки агентов

### Tennessee Eastman Process — семейство референсных реализаций
Классический бенчмарк-симулятор химического процесса Даунса–Фогеля–Браатца — реактор, сепаратор, стриппер, компрессор, с настраиваемыми отказами. Используется с 1993 года.

- **[ccreinartz11/pytep](https://github.com/ccreinartz11/pytep)** — pyTEP, высокоуровневый Python API для интерактивных симуляций. Лучшая точка входа для экспериментов с агентным супервайзингом. (Reinartz & Enevoldsen, SoftwareX 2022)
- **[jkitchin/tennessee-eastman-profbraatz](https://github.com/jkitchin/tennessee-eastman-profbraatz)** — оригинальный Fortran 77 + Python backend через f2py (~5-10× быстрее)
- **[camaramm/tep2py](https://github.com/camaramm/tep2py)** — Python-обёртка над оригинальным Fortran
- **[usnistgov/tesim](https://github.com/usnistgov/tesim)** — от NIST, оптимизирован для wireless и cybersecurity-исследований
- **[ElsevierSoftwareX/SOFTX-D-24-00664](https://github.com/ElsevierSoftwareX/SOFTX-D-24-00664)** — COSTEP, полная открытая Simulink-модель TEP

**Вердикт:** естественная база для бенчмарка агентов управления процессами. pyTEP — рекомендуемая точка входа.

### 🚧 Симуляторы батч-процессов (бетонный узел, гидропоника, пищевая промышленность)
Дискретные и батч-процессы недопредставлены в открытых симуляторах. Контрибуции приветствуются, особенно с реалистичными паттернами алармов.

## 🤖 Советчики и copilots оператора

Каждый заслуживающий доверия советчик оператора сегодня — проприетарный и предшествует текущей LLM-волне. Перечислены для контекста ландшафта.

### 🇷🇺 [Piklema Predictive](https://piklema.com/) 🔒
Хельсинки, русскоязычная команда. Series A ($12.82M, июль 2025). Флагманский продукт **Driver Assistant** — real-time аудио/визуальный советчик для водителей карьерных самосвалов, заявленный эффект **3-5% экономии топлива**. Не управление процессом — оптимизация поведения водителя. Дополнительные продукты для шин, двигателей, усталости.
**Вердикт:** рабочий пример pre-LLM цифрового советчика с измеримым эффектом в узкой нише.

### 🇷🇺 [Zyfra (Цифра)](https://www.zyfra.com/) 🔒
Крупнейший русскоязычный IIoT-вендор. Не отдельный «советчик» — полный стек: платформа ZIIoT, Machine Data Collection (MDC Plus), Zyfra AI (оптимизация через deep learning), Zyfra EYE (computer vision), вертикальные продукты для горнодобычи (Диспетчер, Обзор 360, роботизированное бурение, беспилотный самосвал), нефтегаза, металлургии, химии. Всё pre-LLM AI/ML.
**Вердикт:** референсный «традиционный промышленный ИИ» стек русскоязычного рынка. Включён для понимания ландшафта — с чем LLM-советчикам предстоит сравниваться.

### 🇷🇺 СИПО (Росатом, Нововоронежская АЭС) 🔒
Ядерная система поддержки оператора: ~360 систем, ~200 процедур, прогноз на 30 минут. Публичной реализации или SDK нет.
**Вердикт:** задокументированный в конференц-материалах кейс зрелой архитектуры советчика на объекте высшей критичности.

### 🚧 Open-source LLM-советчик оператора — не найдено

## 📚 Исследования и стандарты

- **ASM Consortium** — [Abnormal Situation Management](https://www.asmconsortium.net/) — фундаментальная работа по человеческим факторам. Ключевой факт: 42% инцидентов имеют человеческий фактор в корне.
- **Siemens True Cost of Downtime 2024** — самое цитируемое исследование экономики простоев ($1,4 трлн/год у Fortune Global 500, 11% выручки)
- **MCP (Model Context Protocol)** — [спецификация](https://modelcontextprotocol.io/) — стандарт, принимаемый промышленными вендорами
- **[GitHub MCP Registry](https://github.com/mcp)** — зарождающийся стандартный каталог MCP
- **ISA-95 / ISA-88 / ISA-101 / ISA-18.2** — промышленные стандарты, которые агенты должны уважать. Публичных работ по формальному встраиванию в guardrails нет.
- 🚧 Open-source реализации логики ISA-18.2 (alarm management) для агентов — не найдено.

## 🧰 Смежные инструменты

Универсальные, но реально полезные при построении промышленных агентных систем:

- **[AgentOps-AI/agentops](https://github.com/AgentOps-AI/agentops)** — Python SDK для мониторинга агентов, трекинга стоимости LLM, session replay. Интегрируется с CrewAI, OpenAI Agents SDK, LangChain, AutoGen, AG2, CamelAI. *Не путать с Microsoft Azure/agentops — это другой продукт.*
- **[stanfordnlp/dspy](https://github.com/stanfordnlp/dspy)** — ~35k звёзд, 5.9M+ загрузок/мес. Фреймворк компилируемых промптов от Stanford NLP. Signatures, modules, optimizers (MIPROv2, GEPA). Актуален для evals-тяжёлых промышленных workflow.
- **[e2b-dev/E2B](https://github.com/e2b-dev/E2B)** — sandbox для исполнения кода агентами. Концептуально родственно shadow-режиму для OT.
- **[topoteretes/cognee](https://github.com/topoteretes/cognee)** — knowledge-graph слой для LLM. Полезно для привязки к регламентам, SOP и P&ID.
